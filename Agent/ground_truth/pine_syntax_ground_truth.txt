1. TOKEN FORMAT
--------------------------------------------------------------------------------
All Pine template expressions are wrapped in @[ and ].

  Syntax: @[expression]

Simple field access:
  @[Respondent.first.NameLastName]

Function call:
  @[Respondent.first.FormatName(F M L)]

Chained method call:
  @[Defendant.first.FormatName(F M L).SetCasing(Upper)]

Nested token (token inside token):
  @[CreateVar(@Defendant, @CaseInvolvement.GetByQuery("CaseID":@[builtin.CaseID],"Type":"DEF"))]

Control keywords (standalone):
  @[If(condition)]
  @[ElseIf(condition)]
  @[Else]
  @[EndIf]
  @[Foreach(varName IN Collection)]
  @[EndForEach]
  @[Cca(expression)]     -- comma-separated concatenation
  @[EndCca]

--------------------------------------------------------------------------------
2. BUILTIN VARIABLES
--------------------------------------------------------------------------------
These are system-provided variables always available without CreateVar.

  @[builtin.CaseID]                       -- current case numeric ID
  @[builtin.CurrentUserPersonnelID]       -- logged-in user's personnel ID
  @[builtin.CurrentUserUserID]            -- logged-in user's system user ID
  @[builtin.Today]                        -- today's date (raw)
  @[builtin.today.FormatDate(preset1)]    -- today formatted: MMMM d, yyyy
  @[builtin.Today.FormatDate(preset2)]    -- today formatted: d day of MMMM, yyyy
  @[builtin.today.FormatDate(preset3)]    -- today formatted: MMMM, yyyy
  @[builtin.Today.FormatDate(preset5)]    -- today formatted: MM/dd/yyyy
  @[builtin.today.FormatDate(yyyy)]       -- 4-digit year only
  @[builtin.Today.FormatDate(dddd)]       -- full weekday name (e.g. Monday)
  @[builtin.Today.FormatDate(MMMM)]       -- full month name

NOTE: "builtin.today" and "builtin.Today" are both observed — casing is flexible.

3. DATE FORMAT PRESETS AND PATTERNS
--------------------------------------------------------------------------------
Preset shortcuts (authoritative from official help page):
  preset1  →  MMMM d, yyyy              (e.g. April 13, 2026)
  preset2  →  {d} day of {MMMM}, {yyyy} (e.g. 13th day of April, 2026)  — ordinal day
  preset3  →  MMMM, yyyy                (e.g. April, 2026)
  preset4  →  M/d/yyyy                  (e.g. 4/13/2026)   — single-digit month/day
  preset5  →  MM/dd/yyyy                (e.g. 04/13/2026)  — zero-padded month/day
  preset6  →  M/dd/yyyy                 (e.g. 4/13/2026)   — single-digit month, padded day

NOTE: preset4 was previously undocumented. It is NOT the "occurrence date format" —
it is M/d/yyyy (no zero-padding). preset5 and preset6 differ only in month padding.

FormatDate uses standard C# date format strings. The engine accepts any valid C# format.

IMPORTANT: Always prefer presets over raw format strings when they match.
For example, legacy FormatDate(CurrentDate(), MMMM d, yyyy) should become
@[builtin.today.FormatDate(preset1)], NOT @[builtin.today.FormatDate(MMMM d, yyyy)].
The preset form is the correct Pine idiom.

Custom patterns (only when no preset matches):
  @[someDate.FormatDate(MMMM d, yyyy)]
  @[someDate.FormatDate(M/dd/yyyy)]
  @[someDate.FormatDate(yyyy)]
  @[someDate.FormatDate(h:mm tt)]        -- 12-hour time with AM/PM
  @[someDate.FormatDate(HH:mm t.t.)]     -- 24-hour time
  @[someDate.FormatDate(dddd)]           -- weekday name
  @[someDate.FormatDate(dddd MMMM d, yyyy)]
  @[someDate.FormatDate(dddd, MMMM d, yyyy)]
  @[someDate.FormatDate(dddd, MMMM d, yyyy,  h:mm tt)]

Combined date + time examples:
  @[SubEvent.StartDate.FormatDate(preset1)] at @[SubEvent.StartDate.FormatDate(h:mm tt)]
  @[PTREvent.StartDate.FormatDate(dddd, MMMM d, yyyy,  h:mm tt)]
  @[e.StartDate.FormatDate(dddd, MMMM d, yyyy)] at @[e.StartDate.FormatDate(h:mm tt)]
  @[FEV.first.StartDate.FormatDate(dddd, MMMM d)]    -- date without year
  @[PleaDeadline.StartDate.FormatDate(dddd MMMM d, yyyy)]  -- no comma after weekday (alternate form)

NOTE: Both "dddd, MMMM d, yyyy" (with comma) and "dddd MMMM d, yyyy" (no comma) are observed.

4. SELECTORS — ACCESSING COLLECTION ITEMS
--------------------------------------------------------------------------------
When a variable holds multiple records, use a selector to access one:

  .first      -- first record in collection
  .last       -- last record in collection (also .Last())
  .first()    -- method form (chaining)
  .Last()     -- method form (chaining)
  .Any()      -- boolean: true if collection has at least one record
  .IsLast     -- boolean property on a ForEach loop variable: true when on last item

Examples:
  @[Defendant.first.NameLastName]
  @[Charges.first.CaseChargeID]
  @[Charges.Last().CaseChargeID]
  @[DefAtty.first.FormatName(F M L)]
  @[Charges.Any()]
  @[If(@[x.IsLast])]  -- inside ForEach, test if current item is the last one

5. FORMATNAME — NAME FORMATTING FUNCTION
--------------------------------------------------------------------------------
Syntax: @[variable.FormatName(format)]

Format tokens (authoritative from official help page):
  F    = First name
  M    = Middle name
  L    = Last name
  P    = Prefix  (e.g. "Mr.", "Ms.", "Hon.")
  S    = Suffix  (e.g. "Jr.", "Sr.", "III")
  I    = Initial (first letter)
  IL   = first + last initials
  FILI = First name + initials of remaining names (common for attorneys)

NOTE: If the name belongs to a business, FormatName will display the business name
regardless of the format tokens used.

Format examples and output:
  FormatName(F M L)    → "John Test Doe"
  FormatName(P F M L S) → "Mr John Test Doe Sr"
  FormatName(L, F)     → "Doe, John"        (comma separator between tokens)
  FormatName(L, F M)   → "Doe, John Test"
  FormatName(F L)      → "John Smith"
  FormatName(L)        → "Smith"
  FormatName(F L).SetCasing(Title)   → "John Smith"
  FormatName(F L).SetCasing(Upper)   → "JOHN SMITH"
  FormatName(FILI)                   → "John M.S." (first + initials)
  FormatName(IL)       → "JD"   (all initials, no spaces)
  FormatName(IML)      → "JTD"  (initials of all name parts)

IMPORTANT — comma separator form:
  A comma between tokens produces "Last, First" style output:
  @[Defendant.FormatName(L, F M)]  → "Doe, John Test"
  This is distinct from space-separated tokens which produce "First Last" style.

IMPORTANT — FormatName vs. direct field access:
  FormatName is used ONLY when you need a combined/formatted name in a SINGLE token,
  such as signatures, salutations, or inline full-name references.
  When the template shows first name and last name as SEPARATE placeholders,
  use the direct field accessors instead:
    CaseInvolvement fields: .NameFirstName, .NameLastName
    Personnel fields:       .PersonnelFirstName, .PersonnelLastName

  CORRECT (separate placeholders):
    @[Respondent.first.NameFirstName] @[Respondent.first.NameLastName]
    @[RespondentAtty.first.PersonnelFirstName] @[RespondentAtty.first.PersonnelLastName]
  INCORRECT (do NOT use FormatName for separate first/last):
    @[Respondent.first.FormatName(F L)]   ← wrong when first and last are separate tokens

  CORRECT (single combined name display — signatures, inline):
    @[OBAAttorney.first.FormatName(FILI)]
    @[cu.FormatName(FILI)]
    @[Defendant.first.FormatName(F M L).SetCasing(Upper)]

Real examples:
  @[OBAAttorney.first.FormatName(FILI)]   -- signature initials
  @[cu.FormatName(FILI)]                  -- current user initials
  @[Defendant.first.FormatName(F M L)]    -- full inline name
  @[Defendant.first.FormatName(F M L).SetCasing(Upper)]  -- full name uppercase
  @[Prosecutor.first.FormatName(F L).SetCasing(Title)]

6. SETCASING — TEXT CASING MODIFIER
--------------------------------------------------------------------------------
Can be chained after FormatName or on any string field.

  .SetCasing(Upper)     -- ALL CAPS
  .SetCasing(Lower)     -- lowercase
  .SetCasing(Title)     -- Title Case  (each word capitalized)
  .SetCasing(Sentence)  -- Sentence case  (first word capitalized only)

Examples:
  @[Defendant.first.FormatName(F M L).SetCasing(Upper)]
  @[Defendant.first.NameFirstName.SetCasing(Upper)]
  @[ChildName.Gender.GetLabel(98).SetCasing(Lower)]
  @[Initials.SetCasing(Upper)]
  @[Prejudice.SetCasing(Upper)]

NOTE: Uppercase method forms also observed in some templates:
  @[DEFENDANT.FIRST.NAMEFIRSTNAME.SETCASING(UPPER)]  (syntax is case-insensitive)

7. GETLABEL — CODE-TO-LABEL LOOKUP
--------------------------------------------------------------------------------
Converts a stored code to a human-readable label using a lookup table.

  Syntax: @[field.GetLabel(tableID)]
  Also chained: @[field.GetLabel(tableID).SetCasing(Lower)]

The table identifier can be either a NUMERIC ID (legacy, seen in real templates)
or a NAMED STRING (official form from help page). Both are valid.

Named string options → legacy numeric ID mapping (where known):
  CaseAssignmentType       →  6    (e.g. "Lead Prosecutor", "Public Defender")
  CaseChargeStage          →  12
  EventType                →  27   (e.g. "Jury Trial", "Sentencing")
  CaseInvolvementType      →  48   (e.g. "Mother", "Guardian")
  CasePleaType             →  59
  NameEyeColor             →  97
  NameGender               →  98   (e.g. "Male", "Female")
  NameHairColor            →  99
  NameRace                 →  101
  PersonnelElementSubtype  →  121  (court division label)
  NamePrefix               →  130  (e.g. "Mr.", "Ms.", "Hon.")
  SystemStatuteClass       →  160  (charge class label)
  SystemStatuteSeverity    →  217  (e.g. "Felony", "Misdemeanor")

Additional named table identifiers by category (use with GetLabel):
  -- Name/person demographics:  NameGender, NamePrefix, NameSuffix, NameRace, NameEyeColor, NameHairColor, NameEthnicity
  -- Personnel:                 PersonnelPrefix, PersonnelSuffix, PersonnelElementSubtype, PersonnelStatus, PersonnelType
  -- Case:                      CaseStatus, CaseSubtype, CaseAssignmentType, CaseAssignmentStatus
  -- Case charge:               CaseChargeStage, CaseChargeStatus, CaseChargeDecision
  -- Case plea/sentence:        CasePleaType, CasePleaStatus, CaseSentenceType, CaseSentenceStatus
  -- Case disposition:          CaseDispositionType, CaseDispositionStatus, CaseDispositionSubtype
  -- Case involvement:          CaseInvolvementType, CaseInvolvementStatus, CaseInvolvementSubtype
  -- Event:                     EventType, EventStatus, EventAssignmentType, EventAssignmentStatus
  -- System statute:            SystemStatuteSeverity, SystemStatuteClass, SystemStatuteCategory, SystemStatuteStatus
  -- System agency:             SystemAgencyStatus, SystemAgencyType, SystemAgencySubtype
  -- Address/phone/email:       AddressStatus, AddressType, PhoneStatus, PhoneType, EmailStatus, EmailType
  -- Task:                      TaskType, TaskStatus, TaskSubtype

Examples:
  @[ch.Severity.GetLabel(217)]               -- numeric form: "Felony"
  @[ch.Severity.GetLabel(SystemStatuteSeverity)]  -- named form (equivalent)
  @[DefName.Gender.GetLabel(98)]             -- "Male" / "Female"
  @[DefName.Gender.GetLabel(NameGender)]     -- named form (equivalent)
  @[DefName.HairColor.GetLabel(99)]
  @[DefName.EyeColor.GetLabel(97)]
  @[DefName.Race.GetLabel(101)]
  @[e.Type.GetLabel(27)]                     -- event type label
  @[Assign.Type.GetLabel(6)]                 -- role label
  @[g.Type.GetLabel(48)]                     -- involvement type
  @[Division.first.SubType.GetLabel(121)]
  @[DefAttyPersonnel.Prefix.GetLabel(130)]
  @[Plea.first.Type.GetLabel(59).SetCasing(Lower)]
  @[Case.Type.GetLabel(78)]                  -- numeric ID example from help page

9b. FORMATNUMBER — NUMBER MASK FORMATTING
--------------------------------------------------------------------------------
Formats a numeric field using a mask pattern. Use # for each digit.
The field value must contain only digits and must be at least as long as the
number of # characters in the mask. Extra digits are appended without formatting.

  Syntax: @[field.FormatNumber(mask)]

Examples:
  @[DefSSN.Number.FormatNumber(###-##-####)]   -- SSN: "123-45-6789"
  @[DefPhone.PhoneNumber.FormatNumber(###-###-####)]

9c. GETAGE — AGE CALCULATION
--------------------------------------------------------------------------------
Calculates a person's age given a date of birth and a reference date.
Returns the age as an integer number of years.

  Syntax: @[GetAge(@[dateOfBirth], @[referenceDate])]

Examples:
  @[GetAge(@[Def.NameDateOfBirth], @[primaryCharge.Occurred])]
  @[GetAge(@[DefName.DateOfBirth], @[builtin.Today])]

9d. GETDATEDIFF — DATE DIFFERENCE CALCULATION
--------------------------------------------------------------------------------
Calculates the difference between two dates in a specified unit of time.

  Syntax: @[GetDateDiff(@[startDate], @[endDate], "unit")]

  Units (case-insensitive):
    Year    -- difference in whole years
    Month   -- difference in whole months
    Day     -- difference in whole days
    Hour    -- difference in whole hours
    Minute  -- difference in whole minutes

Examples:
  @[GetDateDiff(@[Case.DateReceived], @[builtin.today], "Day")]
  @[GetDateDiff(@[charge.Occurred], @[builtin.Today], "Year")]

10. CONDITIONAL CONSTRUCTS — IF / ELSEIF / ELSE / ENDIF
--------------------------------------------------------------------------------
Syntax:
  @[If(condition)]  ...content...
  @[ElseIf(condition)]  ...content...
  @[Else]  ...content...
  @[EndIf]

Condition forms:
  Equality (string comparison, quotes around token value):
    @[if('@[DefName.Gender]'=='M')]
    @[if('@[DefName.Gender]' == 'Male')]
    @[if('@[myCase.Type]' == 'CT005')]

  Boolean check:
    @[if(@[PubDef.Any()] == true)]
    @[if(@[DefAtty.Any()] == false)]
    @[if(@[ChildSSN.Any()] == true)]

  Null check:
    @[if(@[DefAtty.CaseAssignmentID.IsNullOrEmpty()]==false)]
    @[if(@[Assignment.PersonnelID.IsNullOrEmpty()]==false)]
    @[if(@[MotherName.DateOfBirth.IsNullOrEmpty()]==true)]

  Comparison operators (authoritative from official help page):
    ==    equality
    =     equality (alternate form, observed in templates)
    !=    not equal
    >     greater than
    <     less than
    >=    greater than or equal
    <=    less than or equal
    IN    membership (value is one of a list)

  IN syntax:
    @[If('@[Agency.Code]' IN 'AG01', 'AG02', 'AG03')]  -- comma-separated values
    @[if(@[CaseInfo.Type] IN 'JC001','JC002')]          -- alternate spacing

  Numeric field comparison:
    @[If(@[CseFees.BalanceDue] > 0)]   -- numeric greater-than
    @[If(@[CseFees.BalanceDue] >= 0)]

  Logical operators (in condition):
    &&    logical AND
    ||    logical OR
    Example: @[if('@[myCase.Type]' == 'CT005' || '@[myCase.Type]' == 'CT006')]
    Example: @[If('@[Cse.Type]' == 'CRIMINAL' && '@[Cse.Status]' == 'OPEN')]

  ID comparison:
    @[if(@[c.CaseChargeID]==@[Charges.First().CaseChargeID])]
    @[if(@[c.CaseChargeID]==@[Charges.Last().CaseChargeID])]

Full examples:

Gender pronoun block:
  @[if('@[DefName.Gender]'=='M')]he@[elseif('@[DefName.Gender]'=='F')]she@[else]he/she@[endif]
  @[if('@[DefName.Gender]'=='M')]his@[elseif('@[DefName.Gender]'=='F')]her@[else]his/her@[endif]
  @[if('@[DefName.Gender]'=='M')]him@[elseif('@[DefName.Gender]'=='F')]her@[else]him/her@[endif]
  @[if('@[DefName.Gender]'=='M')]Mr.@[elseif('@[DefName.Gender]'=='F')]Ms.@[else]Mr./Ms.@[endif]
  @[if('@[DefName.Gender]'=='Male')]himself@[elseif('@[DefName.Gender]'=='Female')]herself@[else]himself/herself@[endif]

Salutation for Name Type (business vs. person):
  @[if('@[VicName.Type]' == 'AGY')]To Whom It May Concern@[elseif('@[VicName.Type]' == 'BUS')]To Whom It May Concern@[else]Dear @[endif]

Defense attorney address/defendant fallback:
  @[if(@[DefAtty.Any()] = true)]@[DefAtty.first.FormatName(F M L)]
    @[DefAttyAddress.first.StreetAddress]
    @[DefAttyAddress.first.City], @[DefAttyAddress.first.State] @[DefAttyAddress.first.Zip]
    @[Defendant.first.FormatName(F M L)] c/o counsel
  @[else]@[Defendant.first.FormatName(F M L)]
    @[DefAddress.first.StreetAddress]
    @[DefAddress.first.City], @[DefAddress.first.State] @[DefAddress.first.Zip]
  @[endif]

Case type branching:
  @[if('@[myCase.Type]' == 'CT005')]In the Matter of
  @[elseif('@[myCase.Type]' == 'CT006')]In the Interest of
  @[else]State of Kansas vs.
  @[endif]

CoDefendant plural check:
  @[if(@[CoDefendant.Any()]==true)]S@[else]@[endif]

Severity null check (charge display):
  @[if(@[ch.Severity.IsNullOrEmpty()]==true)]@[else] a @[ch.Severity.GetLabel(217)]@[endif]

NOTE: @[endelse]@[endif] double-close form is also observed (some parser variants):
  @[if(@[DefGender.Gender] == 'M')]he@[elseif(@[DefGender.Gender] == 'F')]she@[else]he/she@[endelse]@[endif]

11. FOREACH / ENDFOREACH — ITERATION
--------------------------------------------------------------------------------
Syntax (collection has ForEach method):
  @[CollectionVar.ForEach(itemVar)] ... @[CollectionVar.EndForEach]

Syntax (standalone Foreach with IN):
  @[Foreach(itemVar IN CollectionVar)] ... @[EndForEach]

Examples:
  @[Charges.ForEach(c)] @[c.SystemStatuteOffense] @[Charges.EndForEach]
  @[Victims.ForEach(vic)] @[vic.FormatName(F M L)] @[Victims.EndForEach]
  @[Events.Foreach(e)] @[e.StartDate.FormatDate(preset1)] @[Events.EndForEach]
  @[EA.ForEach(Assig)] @[Assig.FormatName(F M L)] @[EA.EndForEach]
  @[EI.ForEach(Involve)] @[Involve.FormatName(F M L)] @[EI.EndForEach]
  @[FutureEvents.ForEach(e)]@[if(@[e.Type]=='SNT')]@[e.StartDate.FormatDate(dddd, MMMM d, yyyy)] at @[e.StartDate.FormatDate(h:mm tt)]@[else]@[endif]@[FutureEvents.EndForEach]
  @[RespondentPhone.ForEach(RP)] @[RP.PhoneNumber.FormatPhoneNumber()] @[RespondentPhone.EndForEach]
  @[VWOEmail.ForEach(em)] @[em.EmailAddress] @[VWOEmail.EndForEach]
  @[EIAddr.ForEach(InvolveAddr)] @[InvolveAddr.StreetAddress] @[EIAddr.EndForEach]
  @[AssignPhones.ForEach(AssignPhone)] @[AssignPhone.PhoneNumber] @[AssignPhones.EndForEach]

Accessing First/Last inside ForEach for conditional comma/punctuation:
  @[Charges.ForEach(c)]
    @[if(@[c.CaseChargeID]==@[Charges.First().CaseChargeID])]
      @[c.SystemStatuteOffense]
    @[elseif(@[c.CaseChargeID]==@[Charges.Last().CaseChargeID])] and @[c.SystemStatuteOffense]
    @[else], @[c.SystemStatuteOffense]
    @[endif]
  @[Charges.EndForEach]

Address ForEach (iterating multiple addresses):
  @[RespondentAddress.ForEach(x)]
    @[x.StreetAddress.SetCasing(Title)]
    @[x.City.SetCasing(Title)], @[x.State] @[x.Zip]
  @[RespondentAddress.EndForEach]

  @[DefenseAddress.ForEach(y)]
    @[y.StreetAddress.SetCasing(Title)]
    @[y.City.SetCasing(Title)], @[y.State] @[y.Zip]
  @[DefenseAddress.EndForEach]

IsLast pattern (avoid trailing comma/separator):
  @[Items.ForEach(x)]
    @[x.SomeField]@[If(@[x.IsLast])]@[Else], @[EndIf]
  @[Items.EndForEach]

Ticket numbers with comma separation:
  @[TicketNumbers.Foreach(tn)]@[tn.Number]@[if(@[tn.CaseAgencyID]==@[TicketNumbers.Last().CaseAgencyID])]@[else], @[endif]@[TicketNumbers.EndForEach]

Events enumeration (first / middle / last punctuation):
  @[Events.Foreach(e)]
    @[if(@[e.EventID] == @[Events.First().EventID])]
      @[e.Type.GetLabel(27)] on @[e.StartDate.FormatDate(M/dd/yyyy)]
    @[elseif(@[e.EventID] == @[Events.Last().EventID])], and @[e.Type.GetLabel(27)] on @[e.StartDate.FormatDate(M/dd/yyyy)]
    @[else], @[e.Type.GetLabel(27)] on @[e.StartDate.FormatDate(M/dd/yyyy)]
    @[endif]
  @[Events.EndForEach]

12. CCA / ENDCCA — COMMA-SEPARATED CONCATENATION
--------------------------------------------------------------------------------
Cca generates a comma-separated list from a collection or expression.

  Syntax: @[Collection.Cca(itemVar)] ... content ... @[Collection.EndCca]
  Short form: @[Cca(expression)]

Examples:
  @[Charges.Cca(ch)]@[ch.CountNumber]: @[ch.SystemStatuteCode] @[ch.SystemStatuteOffense]@[Charges.EndCca]
  @[Charges.Cca(ch)]@[ch.CountNumber] ~ @[ch.SystemStatuteCode] @[ch.SystemStatuteOffense]@[Charges.EndCca]
  @[Cca(RelCharges.SystemStatuteOffense)]
  @[Cca(Durations.Agreement)]
  @[Cca(Charges.Occurred.FormatDate(preset1))]
  @[Cca(CoDefendant.FormatName(F M L))]
  @[Cca(IntakeRules)]
  @[Cca(Reasons)]
  @[Children.Cca(child)]@[child.FormatName(F M L)]@[Children.EndCca]
  @[Cca(promCharges(ch))]@[ch.CountNumber] ~ @[ch.SystemStatuteCode] @[ch.SystemStatuteOffense]@[promCharges.EndCca]

NOTE on Cca separator: Cca places ", " between items and " and " before the final item
(Oxford-style comma-and). The short form @[Cca(collection.field)] handles single-field lists.
The complex form @[Collection.Cca(var)]...@[Collection.EndCca] handles multi-field content.

--------------------------------------------------------------------------------
12b. LB / ENDLB — LINE-BREAK-SEPARATED LIST
--------------------------------------------------------------------------------
Lb works like Cca but places a line break between each item instead of a comma.

  Syntax (simple): @[Lb(collection.field)]
  Syntax (complex): @[Collection.Lb(itemVar)] ... content ... @[Collection.EndLb]

Examples:
  @[Lb(caseFlag.Type)]
  @[Charges.Lb(ch)]@[ch.CountNumber] ~ @[ch.SystemStatuteCode] @[ch.SystemStatuteOffense]@[Charges.EndLb]

NOTE: Lb is the line-break equivalent of Cca. Use Lb when each item should appear
on its own line rather than in a comma-separated inline list.

13. CREATEVAR — VARIABLE DECLARATION AND DATA BINDING
--------------------------------------------------------------------------------
Creates a named variable by querying a data source.

  Syntax: @[CreateVar(@varName, @DataSource.QueryMethod(params))]
  Or with chained .first: @[CreateVar(@varName, @DataSource.GetByQuery(params)).first]

The @ prefix on the variable name is the declaration marker.
After creation, use the variable WITHOUT @ prefix and WITHOUT @[ ]:

  NameAddress             -- addresses for a Name record
  NamePhone               -- phone numbers for a Name record
  NameEmail               -- email addresses for a Name record
  NameNumber              -- ID numbers (SSN, DL, DOC) for a Name record
  Personnel               -- personnel record (staff/attorneys)
  PersonnelAddress        -- addresses for a Personnel record
  PersonnelPhone          -- phone numbers for a Personnel record
  PersonnelEmail          -- email addresses for a Personnel record
  PersonnelNumber         -- ID numbers for a Personnel record

  SystemUser              -- system login user record
  SystemAgency            -- agency/court entity
  SystemAgencyAddress     -- address for a system agency
  SystemStatute           -- statute/rule definition record (charge rule metadata)

IMPORTANT — SetCasing on address fields:
  In most OBA/bar templates, address fields do NOT use .SetCasing(Title).
  Even when the legacy template wraps a field in TitleCase(), the correct
  Pine syntax is typically the plain field WITHOUT SetCasing.
  Only add .SetCasing(Title) if the Pine template explicitly requires it
  (e.g., some criminal/PD templates).

  CORRECT (OBA/bar context — most common):
    @[RespondentAddress.first.City]
    @[RespondentAttyAddress.first.City]
    @[ComplainantAddress.first.City]
  INCORRECT (do NOT add SetCasing unless explicitly needed):
    @[RespondentAddress.first.City.SetCasing(Title)]   ← wrong for OBA context

Address block inline pattern (standard):
  @[DefAddr.first.StreetAddress]
  @[DefAddr.first.City], @[DefAddr.first.State] @[DefAddr.first.Zip]

Address block with SetCasing (only in specific PD/criminal templates):

29. SYNTAX NOTES AND EDGE CASES
--------------------------------------------------------------------------------

Case sensitivity:
  - Pine token keywords are case-insensitive in practice
  - @[if()] and @[If()] and @[IF()] are equivalent
  - @[endif] and @[EndIf] are equivalent
  - .first and .First() are equivalent
  - .last and .Last() are equivalent
  - .FormatName and .formatName are equivalent
  - .SetCasing and .setcasing are equivalent

Nested tokens:
  Tokens can be nested — the inner @[...] resolves first, then the outer.
  Example: @[CreateVar(@DefName,@Name.GetByID(@[Defendant.first.NameID]))]

Boolean comparisons:
  Both == and = are used for equality; == is preferred for string comparisons.
  @[if(@[DefAtty.Any()] = true)]     -- "=" form observed
  @[if(@[DefAtty.Any()] == true)]    -- "==" form also observed

Array type filters (multiple types in one query):
  "Type": "[DEF,CO]"     -- bracket notation
  "Type": ['DU001']       -- single-item array notation
  "Type": ['TC001','TC002','TC003']

CaseID bracket notation (alternate form):
  "CaseID": @[builtin.CaseID]         -- standard
  "CaseID": [@[builtin.CaseID]]       -- array-wrapped form (also valid)

Accessing variables without .first (when variable was pulled as .first at creation):
  @[CreateVar(@Sentence,...)).first]      → @[Sentence.FieldName]  (no .first needed)
  @[CreateVar(@Defendant,...)]            → @[Defendant.first.FieldName]

Direct field access on a ForEach loop variable:
  In @[Charges.ForEach(c)]: access fields directly as @[c.SystemStatuteOffense]

ForEach loop variable does NOT use .first:
  CORRECT:   @[c.SystemStatuteOffense]
  INCORRECT: @[c.first.SystemStatuteOffense]  (don't use .first on loop variable)

EndForEach closing tags:
  @[Collection.EndForEach]    -- standard
  @[EndForEach]               -- standalone form (used with Foreach(X IN Y) syntax)

Prompt variables behave like simple string tokens:
  @[PromptName]   -- renders the user-entered value at generation time
  Prompts can also have FormatDate chained: @[DateOfLetter.FormatDate(preset1)]
  Prompts can be used in If conditions: @[If(@[Subpoena] == 'Y')]

"builtIn.CaseID" alternate casing observed (capital I):
  @[CreateVar(@CaseInfo,@Case.GetByID(@[builtIn.CaseID]))]
  Both @[builtin.CaseID] and @[builtIn.CaseID] are observed — casing is flexible here too.

Accessing PersonnelID directly on a CaseAssignment variable without .first (inside ForEach):
  @[DefAtty.PersonnelID]   -- valid inside @[EA.ForEach(DefAtty)] context
  @[CreateVar(@DefAttyBarNo,@PersonnelNumber.GetByQuery("PersonnelID":@[DefAtty.PersonnelID]))]

Address fields accessed without .first when CreateVar returns a single record:
  @[InvAddress.City]       -- valid when @InvAddress was created with direct result (not collection)
  @[AssignAddress.City]    -- same pattern
  This contrasts with the normal @[DefAddr.first.City] collection pattern.

CaseAssignment FormatName — accessing name directly on assignment variable:
  @[Assignment.FormatName(F M L)]   -- FormatName can be called directly on a CaseAssignment var
  @[Involvement.FormatName(F M L)]  -- and on a CaseInvolvement var in ForEach
  Without going through a Personnel or Name record lookup first.

30. JDA / LEGACY VARIABLE MAPPING GUIDE
--------------------------------------------------------------------------------
When converting legacy JDA templates (using %[...] syntax) to Pine (@[...]),
the following prefix and entity mappings apply.

Entity prefix mapping (JDA → Pine):
  Cust_Respondent / JW_Respondent       →  Respondent       (CaseInvolvement, type RES)
  Cust_Complainant / JW_Complainant     →  Complainant      (CaseInvolvement, type COM)
  Cust_RespondentAtty                   →  RespondentAtty   (CaseAssignment)
  Cust_OBAAttorney                      →  OBAAttorney      (CaseAssignment, type OBA)
  JW_CurrentUser                        →  cu               (current user shorthand)
  JW_CaseDetails                        →  (various — see field mappings below)
  Cust_Defense / JW_Defense             →  Defense          (CaseAssignment — respondent's attorney)
  Cust_Prosecutor / JW_Prosecutor       →  Prosecutor       (CaseAssignment, type PROSATTY)
  Cust_Investigator                     →  Investigator     (CaseAssignment — investigator)
  JW_FilingComplainant                  →  FilingComplainant (CaseInvolvement — filing complainant)
  Cust_IntakeProsecutor                 →  IntakeProsecutor (CaseAssignment — intake prosecutor)

Field mapping (JDA → Pine):
  .FullName            →  .NameFirstName + .NameLastName (for CaseInvolvement entities)
                          .PersonnelFirstName + .PersonnelLastName (for CaseAssignment entities)
                          NOTE: Do NOT use .FormatName(F L) when the original has separate first/last placeholders
  .FirstName           →  .NameFirstName (involvement) or .PersonnelFirstName (assignment)
  .LastName            →  .NameLastName (involvement) or .PersonnelLastName (assignment)
  .MrMs                →  NOT directly mapped in Pine. Use gender-based conditional:
                          @[if('@[Name.Gender]'=='M')]Mr.@[elseif('@[Name.Gender]'=='F')]Ms.@[else]Mr./Ms.@[endif]
                          Or omit if the Pine template does not include a salutation.
  .Title               →  .PersonnelTitle (for personnel) — but verify the Pine template uses it
  .Address             →  .StreetAddress
  .City                →  .City
  .StateCode           →  .State
  .Zip                 →  .Zip
  _RosterAddress       →  Address entity (e.g., RespondentAddress, RespondentAttyAddress)
  _MailAddress         →  Address entity (e.g., ComplainantAddress)

Address entity mapping:
  JW_Respondent_RosterAddress           →  RespondentAddress
  Cust_RespondentAtty_RosterAddress     →  RespondentAttyAddress
  Cust_Complainant_MailAddress          →  ComplainantAddress
  JW_Complainant_RosterAddress          →  ComplainantAddress

Case details mapping:
  JW_CaseDetails.ProsNum                →  @[ProsNum.first.Number]
  UpperCase(JW_CaseDetails.ProsNum)     →  @[ProsNum.first.Number.SetCasing(Upper)]
  NOTE: ProsNum is a CaseAgency variable and ALWAYS requires .first.Number

Function mapping (JDA → Pine):
  FormatDate(CurrentDate(), MMMM d, yyyy)  →  @[builtin.today.FormatDate(preset1)]
  TitleCase(field)                          →  In OBA context, usually just the plain field
                                               (e.g., TitleCase(City) → .City, NOT .City.SetCasing(Title))
  LowerCase(Initials(X.FullName,false))     →  @[cu.FormatName(FILI)]  (no SetCasing needed)
  Initials(X.FullName,false)                →  FormatName(FILI)
  UpperCase(field)                          →  .SetCasing(Upper)

Conditional mapping (JDA → Pine):
  If(Cust_RespondentAtty.FullName.IsEmpty=true)  →  @[If(@[RespondentAtty.Any()] == true)]
    NOTE: JDA checks "IsEmpty=true" (no attorney), but Pine uses .Any() to check existence.
    When JDA says "if FullName is empty, show X, else show Y" the logic inverts:
      JDA:  %[If(Cust_RespondentAtty.FullName.IsEmpty=true)]  (no atty block)
            %[Else] (has atty block)
      Pine: @[If(@[RespondentAtty.Any()] == true)]  (has atty block)
            @[Else] (no atty block)
    The Else/EndIf structure may need to be swapped when the condition is inverted.

Prompt variable mapping (JDA → Pine):
  JDA prompt variables follow a distinctive pattern: %[Name.Name] where both parts
  are identical (e.g., %[DateofLetter.DateofLetter]). These are user-entered values
  at document generation time. In Pine, they become simple @[PromptName] tokens.

  Common prompt variable mappings:
    %[DateofLetter.DateofLetter]                  →  @[DateOfLetter]
    %[DateofLettertoC.DateofLettertoC]            →  @[LetterToComplainantDate]
    %[DateLetterReceived.DateLetterReceived]       →  @[DateLetterReceived]
    %[ResponseDueDate.ResponseDueDate]             →  @[ResponseDueDate]
    %[DateofCtOrder.DateofCourtOrder]              →  @[DateOfCourtOrder]
    %[PRCMeeting.DateofPRC]                        →  @[PRCMeeting]
    %[ARCDates.Dates]                              →  @[ARCDates]

  When the legacy template uses FormatDate on an event date AS a letter date
  (e.g., %[FormatDate(JW_DocumentEvents.EventDt,MMMM d, yyyy)]), and the CONTEXT
  is a letter date heading, this should map to the appropriate letter date prompt
  variable (e.g., @[DateOfLetter]) rather than a data-bound expression.

  Rule: If the JDA variable name follows the X.X pattern (Name.Name), it is always
  a prompt variable. Convert it to @[CleanedCamelCaseName].

OBAAttorney.Title mapping:
  Legacy %[Cust_OBAAttorney.Title] would map to @[OBAAttorney.first.PersonnelTitle].
  However, many Pine templates do NOT include the PersonnelTitle field — they use the
  attorney's name and initials instead. Only produce @[OBAAttorney.first.PersonnelTitle]
  if you are confident the template context requires it. When in doubt, use
  'No mapping found' for %[Cust_OBAAttorney.Title].
