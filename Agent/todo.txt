Agent Performance TODO
======================

1. [+] Stop passing `+ state["messages"]` to every node's LLM call
       - Each node appends its response to messages via the reducer, AND sends all prior messages in the prompt
       - This causes snowballing token counts as each node re-sends all previous responses
       - Instead, only pass state fields each node actually needs (extracted_legacy_info, mapped_pine_info, etc.)
       - The mapping node may still need messages for the tool call loop, but the others don't

2. [ ] Only embed RTF templates in nodes that actually need them
       - Currently every node gets both legacy_template and example_pine_template in its system message
       - extraction_planning: needs both (analyzing the template)
       - extraction: needs legacy_template only (extracting from it)
       - mapping_planning: needs neither full template — just needs to plan how to use the RAG tool
       - mapping: needs both (mapping legacy vars to pine with reference)
       - pine_template_generation: needs both + the mappings

3. [+] Cache the RAG tool — call get_rag_tool() once and reuse
       - In agent.py, get_rag_tool() is called 3 separate times (lines 37, 39, 41)
       - Each call creates a new Chroma connection and tool instance
       - Call it once at the top and pass the same instance to bind_tools, ToolNode, etc.

4. [+] Consider using gpt-4.1-mini for non-reasoning steps
       - Planning and extraction steps don't benefit much from chain-of-thought reasoning
       - gpt-5-mini (reasoning model) spends extra reasoning tokens proportional to prompt complexity
       - Use gpt-4.1-mini for extraction_planning, extraction, mapping_planning
       - Keep gpt-5-mini for mapping and pine_template_generation where reasoning helps

5. [+] Fix max_tokens for gpt-5-mini (reasoning model)
       - Reasoning tokens share the max_tokens budget with output tokens
       - If the budget is too low, reasoning consumes it all and output is empty
       - Ensure max_tokens is large enough (16384+) for reasoning model calls

6. [ ] Add token usage logging to each node
       - After each model.invoke() call, log response.response_metadata['token_usage']
       - This shows input_tokens, output_tokens, reasoning_tokens per step
       - Helps you spot which nodes are consuming the most tokens and where the bottleneck is
       - Example: print(f"[node_name] tokens: {response.response_metadata.get('token_usage')}")

7. [ ] Add empty response guards in each node
       - After each model.invoke(), check if response.content is empty
       - If empty, print a warning: "WARNING: empty response from [node_name], check token budget"
       - Prevents silent failures where reasoning eats the entire max_tokens budget

8. [ ] Enable LangGraph debug mode
       - Set environment variable LANGGRAPH_DEBUG=true (in .env or at runtime)
       - This prints step-by-step graph execution: which node is running, state transitions, etc.
       - Helpful for seeing the flow and spotting unexpected loops (e.g. mapping ↔ rag_tool cycling)

9. [ ] Set up LangSmith tracing (recommended)
       - Add to .env:
           LANGCHAIN_TRACING_V2=true
           LANGCHAIN_API_KEY=<your-langsmith-api-key>
           LANGCHAIN_PROJECT=agent-template-migration
       - Gives you a full web UI trace of every LLM call with:
           token usage breakdown, latency per node, full prompts/responses, tool calls
       - Free tier available at smith.langchain.com
       - This is the single best debugging tool for LangGraph agents

10. [ ] Add timing logs to each node
        - Record start/end time of each model.invoke() call
        - Print elapsed time per node so you can see where time is spent
        - Example:
            import time
            start = time.time()
            response = model.invoke(...)
            print(f"[node_name] took {time.time() - start:.1f}s")

11. [ ] Add an llm_calls safety limit
        - Your state tracks llm_calls but nothing checks it
        - Add a conditional check to prevent infinite loops (e.g. mapping ↔ rag_tool)
        - Example: if state['llm_calls'] > 15, force exit the mapping loop

12. [ ] Cache plans to disk to skip planning LLM calls on subsequent runs
        - Save generated extraction/mapping plans to files (e.g. plans/extraction_plan.txt)
        - On next run: if plan file exists, load from disk and skip the planning LLM call
        - If re-planning is needed (e.g. errors in output), delete the file or pass force_replan=True
        - This eliminates 2 LLM calls on every run after the first
